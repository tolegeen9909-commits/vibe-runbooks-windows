# Диагностика Mac mini 24/7

## Безопасный порядок

1. Повтори самую короткую проверку текущей фазы.
2. Исправь только первый `FAIL` или один ручной сценарий `MANUAL`.
3. Повтори ту же проверку.
4. Не переходи дальше, пока результат не понятен.

Не отключай Firewall или FileVault «для проверки», не открывай TCP/22 на роутере и не создавай новый удалённый канал в обход Tailscale. Не присылай в чат полный вывод Tailscale, `gh auth status`, SSH debug, AnyDesk ID, hostname, IP, email, recovery key, пароль, private key, token или 2FA-код.

`PASS` — состояние доказано локально. `WARN` — есть ограничение, которое нужно прочитать. `FAIL` — обязательное условие не выполнено. `MANUAL` — результат можно доказать только с другого устройства, после reboot или физическим тестом.

## После reboot Mac недоступен

Сначала вспомни выбранный режим.

### Режим `secure`

При включённом FileVault ожидание локальной разблокировки после старта нормально. До неё пользовательский Tailscale и другие login items могут не работать.

Одно действие: разблокируй FileVault и войди локально. Не запускай приложения вручную. Затем с Windows по одному проверь Tailscale, новый SSH/Termius-сеанс и AnyDesk.

Если доступ появился, Mac остаётся кандидатом на `secure-ready`, но не на `autonomous-ready`.

### Режим `autonomous`

Если пришлось касаться Mac, текущий autonomous reboot-тест не пройден. Восстанови доступ локально и проверь только первый пункт:

1. Выполни read-only проверку режима:

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

2. Если mode-состояние верно, проверь, запустился ли Tailscale после входа.
3. Затем отдельно проверь AnyDesk startup/Unattended Access.

После одного исправления повтори полный reboot из фазы 07 при физическом доступе. Старый маркер не заменяет новый тест.

## После Lock Screen доступ пропал

Разблокируй Mac локально. Проверь по одному:

- Tailscale всё ещё online;
- сохранённый SSH/Termius-хост открывает новый сеанс;
- у AnyDesk есть Screen Recording для изображения и Accessibility для управления.

Не выдавай AnyDesk Full Disk Access, если передача файлов действительно не нужна. После изменения одного TCC-разрешения полностью закрой и снова открой AnyDesk, затем повтори lock-тест.

## После Log Out доступ пропал

Logout завершает пользовательские GUI-процессы. Даже при automatic login обычный ручной logout не обязан снова войти автоматически.

Войди локально в выбранную учётную запись и не запускай Tailscale или AnyDesk вручную. Если они не появились сами, исправь login item только одного приложения и повтори logout-тест. Маркер `logout-recovery` означает восстановление после обычного входа без ручного запуска приложений, а не гарантированный доступ на login screen.

## Tailscale не показывает Mac online

Запусти только безопасную проверку:

```bash
bash ./mac-mini-24x7/05-tailscale/verify.sh
```

Далее проверь один пункт за раз в официальном клиенте:

- клиент запущен;
- вход не истёк;
- Mac и Windows находятся в одном tailnet;
- политика tailnet разрешает нужное соединение;
- устройство не требует повторной авторизации.

Не публикуй сырой `tailscale status`: он может содержать адреса, имена устройств и аккаунтов. Не включай публичный port forwarding как обход.

## SSH работает по LAN, но не через Tailscale

Сначала добейся, чтобы Mac был online в Tailscale на обоих устройствах. Затем проверь сохранённый Termius-хост с tailnet-именем, а не публичным адресом.

Если соединение доходит до SSH, но вход отклоняется, проверь:

- выбран правильный локальный пользователь;
- в Termius выбрана нужная identity;
- на Mac установлен только соответствующий **public** key;
- private key остаётся на клиентском устройстве.

Не включай парольный SSH и не присылай private key. При предупреждении о смене host key не удаляй запись вслепую: сначала физически подтверди fingerprint на Mac, особенно если система не переустанавливалась.

После одного исправления повтори:

```bash
bash ./mac-mini-24x7/03-ssh-termius/verify.sh
```

Затем снова проверь соединение с Windows.

## AnyDesk показывает экран, но не управляет

На Mac локально открой **System Settings → Privacy & Security**.

1. Проверь Screen Recording для AnyDesk.
2. Повтори подключение.
3. Только если управление всё ещё не работает, проверь Accessibility.

Меняй одно разрешение за раз. После изменения перезапусти AnyDesk, если macOS просит это сделать. Пароль Unattended Access и 2FA-код вводятся только локально; AnyDesk ID не добавляется в state и не отправляется в чат.

## AnyDesk не принимает Unattended Access после reboot

Убедись, что локальный пользователь уже вошёл согласно выбранному режиму. Затем проверь по одному:

- AnyDesk запускается без ручного открытия;
- Unattended Access по-прежнему включён;
- ACL допускает только ожидаемый аккаунт или устройство;
- 2FA работает и резервные коды хранятся вне репозитория.

После исправления повтори полный reboot-тест. Успех до reboot недостаточен.

## Mac не стартовал после возврата питания

Нажми кнопку питания один раз, чтобы безопасно вернуть локальный доступ. Не повторяй аварийное отключение сразу.

Затем выполни:

```bash
bash ./mac-mini-24x7/02-power-24x7/verify.sh
```

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

Запускай команды по одной. Проверь в **System Settings → Energy** доступную именно этой модели настройку запуска после восстановления питания. Если требуется снова выполнить `sudo pmset -a autorestart 1`, используй точный approval-gate из фазы 06.

Новый power-loss тест разрешён только при физическом доступе, актуальном backup и отсутствии обновлений, шифрования и несохранённой работы.

## Mac стартовал после питания, но удалённого доступа нет

- В `secure` сначала локально разблокируй FileVault. Это ожидаемый предел режима.
- В `autonomous` проверь, состоялся ли automatic login. Затем исправляй автозапуск только одного приложения: сначала Tailscale, потом AnyDesk.

SSH по публичному интернету не открывай. После исправления повтори полный power-loss тест из фазы 08; обычный reboot не заменяет его.

## AnyDesk даёт чёрный экран без монитора

Верни кабель монитора, чтобы восстановить локальное изображение. Затем:

1. Повтори проверку Screen Recording.
2. Обнови только официальный AnyDesk, если установленная версия устарела.
3. Снова отсоедини монитор по процедуре фазы 08 и создай **новое** подключение.

Если конкретная модель не создаёт виртуальный дисплей, может понадобиться совместимый headless display adapter. Это отдельная покупка и отдельный физический тест; не выбирай случайное устройство только ради обхода проверки. SSH должен работать и без графического дисплея.

## Homebrew установлен, но `brew` не найден

Закрой Terminal, открой новый и выполни:

```bash
command -v brew
```

Если результата нет, вернись к выводу `Next steps` официального установщика Homebrew. Покажи одну предложенную им строку целиком и получи approval перед изменением shell profile. Не копируй `/opt/homebrew` с Apple Silicon на Intel или `/usr/local` в обратную сторону вслепую.

## Инструмент разработки не найден

Открой новый Terminal и выполни read-only поиск:

```bash
command -v git gh node npm python3 codex claude
```

Не добавляй случайные каталоги в `PATH`. Вернись к первому `FAIL`:

```bash
bash ./mac-mini-24x7/09-development/verify.sh
```

Повтори только официальный install-шаг этого инструмента. Не запускай `sudo npm`, не изменяй Apple-controlled Python и не используй неизвестный mirror.

## GitHub, Codex или Claude снова просит вход

Проверяй сервисы по одному. Используй только команды и отдельные сетевые approval-gates из фазы 09:

- `gh auth login --web --git-protocol https` для GitHub;
- `codex` и **Sign in with ChatGPT** для Codex;
- `claude` и официальный authentication flow для Claude Code.

Не передавай в чат browser/device code, email, token или сырой статус аккаунта. Если браузер нельзя открыть удалённо, остановись и используй официальный device flow, описанный текущей документацией поставщика; не вставляй токен в командную строку наугад.

## Progress-файл повреждён или содержит лишние поля

Не исправляй readiness ручной установкой `true` и не добавляй заметки. Сравни структуру с `mac-mini-24x7/state/progress-template.json`. Любой сброс progress удалит доказательства и требует отдельного подтверждения; после него соответствующие ручные тесты проходят заново.

Если в state случайно попали IP, имя, email, ID или secret, остановись. Не коммить и не отправляй файл. Удали чувствительное значение безопасным отдельным действием и считай раскрытый credential скомпрометированным, если он успел попасть в Git или чат.
