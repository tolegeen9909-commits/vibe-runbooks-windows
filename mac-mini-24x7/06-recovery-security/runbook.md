# 06 · Восстановление после питания и выбор режима безопасности

## Результат фазы

В этой фазе мы включаем автоматический запуск Mac после возврата питания и выбираем один из двух режимов:

- `secure` — рекомендуемый: FileVault включён, автоматический вход выключен;
- `autonomous` — только явный opt-in: автоматический вход включён, поэтому FileVault придётся выключить.

`secure` лучше защищает данные при физическом доступе. После холодного старта или перезагрузки Mac может ждать локальной разблокировки FileVault; до неё Tailscale, SSH через tailnet и AnyDesk могут быть недоступны. Это нормальное ограничение, а не ошибка.

`autonomous` может вернуть удалённый доступ без человека у Mac, но заметно снижает физическую защиту. Этот режим нельзя выбирать автоматически.

Официальные ориентиры Apple: [FileVault](https://support.apple.com/guide/mac-help/mh11785/mac), [automatic login](https://support.apple.com/guide/mac-help/mchlp1158/mac) и [Energy settings](https://support.apple.com/guide/mac-help/change-energy-settings-mchlp1168/mac). Названия пунктов могут немного отличаться между версиями macOS; не угадывай отсутствующую настройку.

## До начала

Фазы 00–05 должны быть завершены. SSH по Tailscale и AnyDesk уже должны работать. Выполняй только один пункт, затем останавливайся и проверяй результат.

Сначала прочитай проверочный скрипт:

```bash
sed -n '1,240p' ./mac-mini-24x7/06-recovery-security/verify.sh
```

Запусти её до выбора режима:

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

Проверка показывает безопасные состояния autorestart, FileVault и automatic login. До выбора режима итог честно будет `MANUAL`; это не ошибка и не разрешение менять настройку без approval.

Скрипт read-only: он не меняет `pmset`, FileVault или automatic login и не печатает имя пользователя. Сначала исправляется только первый `FAIL`. `MANUAL` означает, что нужен выбор или физическое доказательство.

## Шаг 1. Автозапуск после возврата питания

Если проверка показывает `PASS` для automatic restart after power loss, ничего не меняй и переходи к выбору режима.

Если autorestart выключен, покажи пользователю ровно эту команду:

```bash
sudo pmset -a autorestart 1
```

**Approval-gate:** команда изменит постоянную настройку питания для всех режимов электропитания и запросит пароль администратора локально в Terminal. Она не проверяет фактический запуск после отключения питания. Спроси: «Разрешаешь выполнить именно `sudo pmset -a autorestart 1`?» Дождись отдельного «да». Пароль пользователь вводит только в Terminal и не присылает в чат.

После выполнения снова запусти ту же проверку:

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

Не переходи дальше, пока autorestart не получил `PASS`. Физический тест будет только в фазе 08.

## Шаг 2. Выбор режима

### Рекомендуемый режим `secure`

Выбирай его, если пользователь отдельно не запросил полностью автономный запуск.

Нужное состояние:

- FileVault включён;
- automatic login выключен;
- пользователь понимает, что после холодного старта может понадобиться человек у Mac.

Попроси подтвердить: «Оставляем FileVault включённым и automatic login выключенным; после холодного старта допускается локальная разблокировка. Выбираем `secure`?»

После явного «да» выбор сделан, но state ещё не меняется. Покажи отдельную команду:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh mode secure
```

**Checkpoint-gate:** команда запишет только `selectedMode: secure` и время в локальный `state/progress.json`. Спроси: «Записать именно этот локальный checkpoint? Ответьте `да`». Выполни только после нового «да».

Теперь запусти read-only проверку выбранного режима:

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

Если automatic login включён, покажи точное ручное действие: **System Settings → Users & Groups → Automatically log in as → Off**.

**Approval-gate:** после следующего запуска macOS потребует обычный вход; это повышает защиту, но исключает полностью автономный старт стандартных пользовательских приложений. Спроси: «Разрешаешь вручную выключить automatic login сейчас?» Дождись отдельного «да», затем повтори `06-recovery-security/verify.sh`.

Если FileVault выключен, сначала убедись, что есть актуальный backup и Mac подключён к стабильному питанию. Покажи точное ручное действие: **System Settings → Privacy & Security → FileVault → Turn On FileVault**.

**Approval-gate:** macOS начнёт защищать диск; нужно выбрать официальный recovery-вариант, а потеря и пароля, и recovery-возможности может лишить доступа к данным. Спроси: «Разрешаешь вручную включить FileVault сейчас?» Дождись отдельного «да». Пароль и recovery key остаются только в системном окне и безопасном хранилище вне Mac и репозитория. Не продолжай reboot или power-test, пока шифрование не завершится; повторяй только `06-recovery-security/verify.sh`.

Не переходи дальше, пока проверка выбранного режима не завершится с `PASS`.

### Режим `autonomous` — только по явному решению

Не предлагай этот вариант как исправление ошибки удалённого доступа. Сначала предупреди:

- automatic login позволяет войти в выбранную учётную запись после старта без ввода пароля;
- FileVault и automatic login несовместимы; отключение FileVault оставляет данные менее защищёнными при краже или физическом доступе;
- расшифровка диска может занять много времени, её нельзя прерывать отключением питания;
- пароль, recovery key и 2FA-коды нельзя передавать в чат или сохранять в state;
- статус `autonomous-ready` появится только после реальных reboot, power-loss и headless-тестов.

Попроси пользователя написать своими словами, что он выбирает `autonomous` и принимает снижение физической защиты. Простого общего «продолжай» недостаточно.

После такого подтверждения покажи отдельную команду:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh mode autonomous
```

**Checkpoint-gate:** команда запишет только выбранную политику `autonomous` и время; она ещё не доказывает и не включает автономность. Спроси: «Записать именно этот локальный checkpoint? Ответьте `да`». Выполни только после нового «да».

Теперь запусти read-only проверку выбранного режима:

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

До завершения изменений ожидается `MANUAL`; это не разрешение пропустить проверки.

Если FileVault включён, покажи точное ручное действие: **System Settings → Privacy & Security → FileVault → Turn Off FileVault**.

**Approval-gate:** это начнёт расшифровку диска и снизит защиту данных. Mac должен быть подключён к питанию; обновления и другие перезагрузки не должны идти. Спроси: «Разрешаешь вручную выключить FileVault именно сейчас?» Дождись отдельного «да». Пользователь сам выполняет действие у Mac и вводит пароль только в системном окне.

После этого повторяй read-only проверку, пока расшифровка полностью не завершится:

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

Не включай automatic login, пока проверка не подтвердит, что FileVault выключен.

Затем покажи точное ручное действие: **System Settings → Users & Groups → Automatically log in as → выбрать отдельную локальную учётную запись**.

**Approval-gate:** после следующего старта macOS войдёт в эту учётную запись без пароля; приложения и данные этого пользователя станут доступны человеку с физическим доступом. Спроси: «Разрешаешь вручную включить automatic login для выбранной локальной учётной записи?» Дождись отдельного «да». Пароль вводится только на Mac.

Повтори проверку:

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

Не переходи дальше, пока проверка выбранного режима не завершится с `PASS`.

## Чек-поинт

После подтверждения autorestart и выбранного режима запиши завершение фазы:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh step 06-recovery-security:verified
```

**Checkpoint-gate:** команда добавит только allowlisted step-marker в локальный progress. Покажи её отдельно, спроси «Записать именно этот локальный checkpoint? Ответьте `да`» и дождись нового согласия.

Запись содержит только разрешённые boolean-маркеры. Не добавляй в state имя пользователя, hostname, IP, AnyDesk ID, ключи или заметки.

Следующий шаг: `07-reboot-checkpoint/runbook.md`.
