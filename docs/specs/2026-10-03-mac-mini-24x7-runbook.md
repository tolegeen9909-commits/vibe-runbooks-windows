# Mac mini 24/7 Runbook

## Goal

Добавить в `tolegeen9909-commits/vibe-runbooks-windows` отдельный безопасный маршрут настройки Mac mini как постоянно доступной удалённой машины для вайбкодинга и AI-автоматизаций, не ломая существующий Windows-маршрут.

PDF `mac-mini-24x7-codex-runbook-plan.pdf` используется как исходный план требований, но не добавляется в репозиторий как установщик и не исполняется автоматически.

## Users And Scenarios

- Основной пользователь — новичок, который настраивает Mac mini с локальным доступом и подключается к нему с Windows-компьютера.
- Пользователь проходит маршрут вместе с Codex строго по одному проверяемому шагу.
- После каждого шага Codex ждёт результат или скриншот, проверяет его и только затем продолжает.
- При ошибке Codex выполняет короткую диагностику, предлагает одно минимальное исправление и повторяет ту же проверку.
- После успешной настройки пользователь может подключаться к Mac mini через SSH/Termius по Tailscale и через AnyDesk Unattended Access после перезагрузки или восстановления питания.

## In Scope

- Превратить корневые инструкции в явный маршрутизатор по платформам: Windows использует существующий PowerShell-маршрут, Mac mini 24/7 использует только новый macOS-маршрут.
- Сохранить существующие Windows-фазы и их поведение; не смешивать Windows- и macOS-команды в одном маршруте.
- Добавить отдельное пространство `mac-mini-24x7/` со своими инструкциями для агента, картой маршрута, runbook, диагностикой и безопасными проверками.
- Покрыть этапы: preflight, обновления macOS, режим питания 24/7, Remote Login/SSH, Termius, AnyDesk, Tailscale на Mac и Windows, SSH через Tailscale, автоматическое восстановление после питания, FileVault/автовход, контрольная перезагрузка, безопасный тест восстановления питания, headless-режим и только затем среда разработки.
- Добавить ветки диагностики для типовых проблем после reboot, с SSH, Tailscale и AnyDesk.
- Добавить read-only check/verify-скрипты там, где результат можно надёжно проверить без изменения системных настроек.
- Для любой установки, сетевого входа, команды с `sudo`, изменения системных настроек, перезагрузки, теста питания, FileVault, автоматического входа и unattended-доступа предусмотреть отдельный approval-gate с точным описанием последствий.
- Обновить тесты и CI так, чтобы Windows-проверки продолжали работать, а macOS-маршрут имел отдельные проверки на `macos-latest`.
- Обновить корневую навигацию и документацию репозитория, чтобы оба маршрута были понятны с первой страницы.

## Out Of Scope

- Фактическая настройка или перезагрузка конкретного Mac mini в рамках изменения репозитория.
- Автоматическое отключение FileVault, включение автоматического входа или настройка AnyDesk Unattended Access без отдельного решения пользователя на конкретной машине.
- Хранение IP-адресов, AnyDesk ID, имён пользователей, паролей, recovery keys, API keys, токенов или других секретов.
- Автоматическое физическое отключение питания; runbook должен предусматривать только безопасную ручную процедуру с явной остановкой и предупреждением.
- Перенос или переработка существующих Windows-фаз, кроме минимальных изменений маршрутизации, документации и тестовых областей.
- Автоматический merge в `main`, запуск установки на пользовательской машине или production deployment.

## Constraints

- Рабочая ветка `codex/mac-mini-24x7-runbook` основана на `codex/windows-safe-install-rules` из открытого PR #2, чтобы сохранить новые approval-gates. PR #2 является логическим prerequisite перед объединением Mac-маршрута в `main`.
- Новый маршрут располагается в `mac-mini-24x7/`, а не в `07-mac-mini-24x7/`, чтобы не конфликтовать с существующей Windows-фазой `07-checkpoint/`.
- Все пользовательские инструкции — на русском, короткими фразами и для новичка.
- Один шаг — одно действие — одна проверка. Нельзя выдавать весь набор команд для запуска подряд.
- Проверочные скрипты должны быть идемпотентными, по умолчанию read-only, не выводить секреты и возвращать понятный exit code.
- Изменяющие систему команды не должны запускаться скрытно или пакетно; сначала проверяется текущее состояние и необходимость изменения.
- Пароли, 2FA-коды, recovery keys, API keys и токены вводятся только локально в официальных приложениях или системных окнах.
- Источники установки и команды для macOS, Tailscale и AnyDesk должны быть сверены с актуальной официальной документацией перед реализацией.
- Существующий Windows CI должен оставаться зелёным; macOS-документы не должны ошибочно проверяться Windows-only запретами.
- В репозиторий не добавляется исходный PDF, если пользователь отдельно этого не попросит.

## Acceptance Criteria

- При открытии корня Codex сначала определяет выбранный сценарий и не предлагает команды другой ОС.
- Windows-сценарий по-прежнему ведёт по существующим PowerShell-фазам и проходит текущие Windows-тесты без регрессий.
- Mac-сценарий начинается в `mac-mini-24x7/`, ведёт пользователя строго по одному шагу и содержит все этапы из раздела In Scope.
- Runbook сначала проверяет текущее состояние и не переустанавливает уже работающие компоненты.
- Перед каждым внешним, административным, сетевым, изменяющим систему или труднообратимым действием показана точная команда или ручное действие, последствия и отдельная точка подтверждения.
- FileVault и автоматический вход описаны как явный компромисс безопасности; отключение FileVault никогда не считается безусловным требованием маршрута.
- SSH настраивается с безопасным приоритетом ключевой аутентификации; Tailscale и AnyDesk описаны без сохранения идентификаторов и credentials в репозитории.
- Read-only проверки подтверждают доступные локальные состояния: платформу, версии, питание, SSH, Tailscale, AnyDesk и итоговые критерии без раскрытия секретов.
- Отдельные Windows- и macOS-проверки CI проходят; маршрутизационные тесты не смешивают правила платформ.
- Финальный checkpoint требует доказать после контрольной перезагрузки без ручного запуска приложений: доступность Tailscale, SSH/Termius по Tailscale IP, AnyDesk Unattended Access, отсутствие системного сна и проверенное восстановление после питания.
- Ни в документации, ни в тестовых данных, ни в Git diff нет реальных IP-адресов, AnyDesk ID, пользовательских credentials или секретов.
