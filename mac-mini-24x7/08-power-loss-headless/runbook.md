# 08 · Восстановление питания и headless-режим

## Почему это отдельная рискованная фаза

Только реальное прерывание питания доказывает, что Mac включится после аварии. Такое испытание может повредить несохранённые данные или файловую систему. Его нельзя заменять обычным reboot и нельзя выполнять удалённо в первый раз.

Официальное описание Apple для доступных конкретной модели настроек: [Change Energy settings on a Mac desktop computer](https://support.apple.com/guide/mac-help/change-energy-settings-mchlp1168/mac).

## Стоп-условия

Первый power-loss тест разрешён, только если одновременно выполнены все условия:

- пользователь физически рядом с Mac mini; подключены монитор, клавиатура и мышь;
- есть актуальная резервная копия важных данных;
- **System Settings → General → Software Update** не показывает активное скачивание, установку, подготовку или ожидающую перезагрузку;
- все файлы сохранены, приложения закрыты, длительные команды и копирование завершены;
- FileVault не шифрует и не расшифровывает диск;
- фаза 07 завершена, а SSH/Termius и AnyDesk прямо сейчас работают;
- Mac не подключён к источнику бесперебойного питания, который не даст тесту прервать питание.

Попроси точное подтверждение: «Я рядом с Mac; backup актуален; обновлений, шифрования и несохранённой работы нет». Без этой фразы тест заблокирован. Не предлагай обход.

Перед физическим действием выполни по одной две read-only проверки:

```bash
bash ./mac-mini-24x7/02-power-24x7/verify.sh
```

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

При `FAIL` или `MANUAL` power-loss тест не проводится. До физического отключения все обязательные power/security состояния должны быть `PASS`; шифрование или расшифровка диска не должны идти.

## Шаг 1. Имитация потери питания

Покажи точное ручное действие: **при работающем Mac mini вынуть только его кабель питания из розетки, не трогая сетевой и другие кабели; подождать не меньше 30 секунд; вернуть кабель питания в ту же исправную розетку**.

**Approval-gate:** это аварийно обесточит работающий Mac без штатного завершения macOS. Возможны потеря данных и необходимость локального восстановления. Спроси: «Разрешаешь один раз вручную выполнить именно этот power-loss тест сейчас?» Дождись отдельного «да». Не запускай тест умной розеткой и не выполняй его сам.

После возврата питания не нажимай кнопку включения. Сначала наблюдай, стартовал ли Mac самостоятельно.

- Если Mac стартовал сам, запиши:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual power-startup
```

  Перед записью покажи эту точную команду и получи отдельное «да»: она меняет только локальный boolean-маркер.

- Если Mac не стартовал, нажми кнопку питания для безопасного восстановления доступа, но не записывай маркер. Не повторяй отключение. Перейди в `TROUBLESHOOTING.md`, исправь одну причину и только затем заново пройди стоп-условия.

## Шаг 2. Удалённый доступ после возврата питания

### Для `secure`

Ожидается экран FileVault. Это безопасное поведение.

1. Локально разблокируй FileVault и войди.
2. Не запускай Tailscale или AnyDesk вручную.
3. С Windows проверь Tailscale online, новое SSH/Termius-подключение и управление AnyDesk.

Этот результат доказывает доступ только **после локальной разблокировки**.

### Для `autonomous`

Не трогай клавиатуру, мышь или кнопку питания после возврата электричества. С Windows проверь по одному:

1. Mac самостоятельно появился online в Tailscale.
2. Новое SSH/Termius-подключение по tailnet открылось.
3. AnyDesk Unattended Access дал полноценное управление.

Если понадобилось локальное действие или ручной запуск приложения, autonomous-тест не пройден.

После доказанного результата выбранного режима запиши:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual power-remote-access
```

Перед записью покажи эту точную команду и получи отдельное «да»: она не проверяет канал сама, а только фиксирует уже доказанный результат.

Не сохраняй адреса, hostname, AnyDesk ID или снимки с recovery key.

## Шаг 3. Headless-тест

Сначала восстанови обычную работу после power-loss теста и ещё раз убедись, что оба удалённых канала доступны. Первый headless-тест также выполняется при физическом доступе.

Покажи точное ручное действие: **при работающем Mac отсоединить только кабель монитора от Mac mini; питание, Ethernet, клавиатуру и мышь не трогать**.

**Approval-gate:** графическое разрешение может измениться, а AnyDesk может показать чёрный экран; физический монитор временно исчезнет как путь восстановления. SSH не должен прерваться. Спроси: «Разрешаешь сейчас отсоединить только кабель монитора для headless-теста?» Дождись отдельного «да».

С Windows закрой старые подключения и создай новые:

1. новое SSH/Termius-подключение по tailnet;
2. новое AnyDesk-подключение с видимым рабочим столом и рабочим управлением.

Только если оба новых подключения работают при отключённом мониторе, запиши:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual headless-access
```

Перед записью покажи эту точную команду и получи отдельное «да» на изменение локального progress.

Если AnyDesk показывает чёрный экран или неверное разрешение, верни кабель монитора, исправь одну причину по `TROUBLESHOOTING.md` и повтори только headless-тест. Не повторяй power-loss без необходимости.

## Чек-поинт

После трёх доказанных маркеров — `power-startup`, `power-remote-access` и `headless-access` — запиши фазу:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh step 08-power-loss-headless:verified
```

**Checkpoint-gate:** покажи команду отдельно, объясни, что она добавит только allowlisted step-marker, и дождись отдельного «да».

Следующий шаг: `09-development/runbook.md`.
