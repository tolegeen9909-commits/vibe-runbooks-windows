# 10 · Итоговый чек-поинт

## Что доказывает итог

Итог имеет только один из двух честных статусов:

- `secure-ready` — FileVault включён, automatic login выключен, удалённый доступ проверен после локальной разблокировки; холодный старт может потребовать человека у Mac;
- `autonomous-ready` — пользователь явно принял снижение физической защиты, а reboot, возврат питания и headless-доступ доказаны без локального действия.

`secure-ready` нельзя называть полностью автономным. `autonomous-ready` нельзя присваивать только по настройкам — нужны реальные ручные тесты из фаз 07 и 08.

После завершения фазы 06 checkpoint writer блокирует смену режима, чтобы старые доказательства нельзя было переиспользовать. Для смены нужен отдельный approval-gated полный сброс локального progress; после него маршрут и все ручные доказательства проходят заново.

## Финальная локальная проверка

Сначала ещё раз проверь живое локальное состояние. Запускай по одной команде и останавливайся на первом `FAIL`:

```bash
bash ./mac-mini-24x7/02-power-24x7/verify.sh
```

```bash
bash ./mac-mini-24x7/03-ssh-termius/verify.sh
```

```bash
bash ./mac-mini-24x7/04-anydesk/verify.sh
```

```bash
bash ./mac-mini-24x7/05-tailscale/verify.sh
```

```bash
bash ./mac-mini-24x7/06-recovery-security/verify.sh
```

```bash
bash ./mac-mini-24x7/09-development/verify.sh
```

`MANUAL` здесь означает, что соответствующее доказательство с Windows или физический тест нужно повторить; не превращай его в `PASS` записью marker задним числом.

После успешных проверок прочитай итоговый скрипт:

```bash
sed -n '1,320p' ./mac-mini-24x7/10-final-checkpoint/self-check.sh
```

Затем выполни его:

```bash
bash ./mac-mini-24x7/10-final-checkpoint/self-check.sh
```

Скрипт не меняет macOS и не печатает IP, hostname, email, AnyDesk ID или credentials. Он проверяет allowlisted phase/manual markers и выбранный режим.

- `FAIL` — обязательное условие не выполнено; исправь только первый пункт и повтори ту же проверку.
- `MANUAL` — нет доказательства ручного сценария; вернись в указанную фазу, не ставь маркер задним числом.
- exit code `0` и `secure-ready`/`autonomous-ready` — все предварительные доказательства собраны.

## Критерии `secure-ready`

Перед фиксацией результата пользователь должен подтвердить:

- выбран `secure`;
- FileVault остался включён, automatic login выключен;
- autorestart и отсутствие системного сна проверены;
- Tailscale, SSH/Termius и AnyDesk работают после обычного входа;
- lock, logout recovery и reboot пройдены;
- после power-loss Mac стартовал сам, затем удалённые каналы восстановились после локальной разблокировки без ручного запуска приложений;
- новые SSH и AnyDesk-сеансы работают без монитора;
- пользователь понимает: после холодного запуска потребуется локальная разблокировка FileVault.

Только после exit code `0` и вывода `secure-ready` запиши:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh step 10-final-checkpoint:secure-ready
```

**Checkpoint-gate:** команда добавит только финальный allowlisted marker в локальный progress. Она не меняет FileVault и не создаёт новое доказательство. Покажи команду отдельно и дождись отдельного «да».

## Критерии `autonomous-ready`

Перед фиксацией результата пользователь должен подтвердить:

- выбран `autonomous` отдельным явным решением;
- FileVault выключен, automatic login включён для выбранной локальной учётной записи;
- пользователь понимает риск физического доступа;
- autorestart и отсутствие системного сна проверены;
- после полного reboot никто не касался Mac до успешных Tailscale, SSH/Termius и AnyDesk-проверок;
- после реального power-loss никто не касался Mac до тех же успешных удалённых проверок;
- новые SSH и AnyDesk-сеансы работают без монитора.

Любой локальный вход, нажатие кнопки питания или ручной запуск Tailscale/AnyDesk во время reboot/power-теста означает, что `autonomous-ready` ещё не доказан.

Только после exit code `0` и вывода `autonomous-ready` запиши:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh step 10-final-checkpoint:autonomous-ready
```

**Checkpoint-gate:** команда добавит только финальный allowlisted marker в локальный progress. Она не меняет настройки и не может заменить reboot/power-test. Покажи команду отдельно и дождись отдельного «да».

Никогда не записывай оба финальных маркера.

## Последняя проверка

После записи одного финального маркера снова запусти:

```bash
bash ./mac-mini-24x7/10-final-checkpoint/self-check.sh
```

Финальный маркер не заменяет доказательства и не должен превращать `FAIL` в успех. В `state/progress.json` остаются только allowlisted boolean-маркеры и выбранный режим — без адресов, имён, ID или секретов.

Маршрут завершён только при повторном exit code `0`. Обновление macOS, смена режима, учётной записи, Tailscale/AnyDesk startup-настроек или сетевой схемы требует повторить затронутые проверки перед тем, как снова полагаться на статус.
