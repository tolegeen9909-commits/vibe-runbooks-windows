# 09 · Среда разработки

## Когда можно начинать

Эта фаза начинается только после стабильного удалённого доступа:

- фазы 07 и 08 завершены;
- reboot и возврат питания уже проверены по правилам выбранного режима;
- новые SSH/Termius и AnyDesk-подключения работают без ручного запуска приложений;
- headless-тест пройден.

Если хотя бы один пункт не доказан, вернись к соответствующей фазе. Инструменты разработки не исправляют удалённый доступ.

Устанавливай только отсутствующее. Одно изменение — одна проверка — остановка. Не копируй в чат токены, одноразовые коды, email, имена учётных записей или полный вывод команд входа.

## Официальные источники

Перед установкой сверяй команды с текущими страницами; номера версий намеренно не закреплены:

- [Homebrew Installation](https://docs.brew.sh/Installation)
- [Homebrew Support Tiers](https://docs.brew.sh/Support-Tiers)
- [GitHub CLI](https://cli.github.com/)
- [Node.js Download](https://nodejs.org/en/download)
- [Using Python on macOS](https://docs.python.org/3/using/mac.html)
- [OpenAI Codex CLI](https://learn.chatgpt.com/docs/codex/cli)
- [Anthropic Claude Code setup](https://code.claude.com/docs/en/setup)

Если команда на официальной странице изменилась, остановись и обнови runbook отдельным review. Не угадывай новый package name.

## Поддерживаемая платформа этой фазы

Фазы 00–08 могут работать на совместимом Intel или Apple Silicon Mac mini, но новый Homebrew-backed setup в этой версии runbook разрешён только при двух условиях:

- `uname -m` возвращает `arm64`;
- macOS имеет major version 15 или новее.

Официальный Homebrew `.pkg` поддерживает только Apple Silicon, а актуальный installer больше не является безопасным обещанным путём для Intel. На `x86_64` или macOS ниже 15 остановись: не скачивай и не запускай Homebrew installer, не записывай marker фазы 09 и не выдавай final readiness. Нужен отдельно проверенный architecture-specific addendum по официальным источникам. Уже существующий Homebrew можно только обнаружить read-only проверкой; этот runbook не обещает его поддержку или обновление на такой конфигурации.

## Начальная проверка

Сначала прочитай скрипт:

```bash
sed -n '1,280p' ./mac-mini-24x7/09-development/verify.sh
```

Затем запусти его в read-only режиме:

```bash
bash ./mac-mini-24x7/09-development/verify.sh
```

Скрипт доказывает только наличие команд в `PATH`; он не доказывает вход в GitHub, OpenAI или Anthropic. Эти три входа подтверждаются вручную и не сохраняются в state, чтобы не хранить account identity.

Уже получивший `PASS` инструмент не переустанавливай. Исправляй первый `FAIL`, после чего запускай эту же проверку снова.

## Шаг 1. Command Line Tools

Сначала выполни read-only проверку:

```bash
xcode-select -p
```

Если команда завершилась успешно и показала developer directory, переходи к Homebrew.

Точная команда:

```bash
xcode-select --install
```

**Approval-gate:** команда откроет системное окно Apple и начнёт сетевую загрузку developer tools после ручного подтверждения. Понадобятся место на диске и время; возможен запрос локального пароля. Спроси: «Разрешаешь выполнить именно `xcode-select --install`?» Дождись отдельного «да». Заверши официальный диалог на Mac, затем повтори `xcode-select -p`.

## Шаг 2. Homebrew

Если Homebrew уже получил `PASS`, ничего не меняй.

### Apple Silicon и macOS 15+ — поддерживаемый путь

Сначала покажи адрес [последнего официального release Homebrew](https://github.com/Homebrew/brew/releases/latest). Объясни, что откроется сетевая страница GitHub проекта `Homebrew/brew`, и получи отдельное «да» только на её открытие.

На открытой странице покажи точное ручное действие: скачать файл `Homebrew.pkg`.

**Download-gate:** файл будет загружен на Mac, но ещё не запущен. Спроси: «Скачать именно `Homebrew.pkg` из официального release `Homebrew/brew`? Ответьте `да`». После загрузки ещё раз проверь владельца страницы и имя файла.

**Approval-gate:** точное ручное действие — открыть скачанный `Homebrew.pkg` в macOS Installer и установить в стандартный prefix. Установщик изменит системные каталоги Homebrew и может запросить локальный пароль. Спроси: «Разрешаешь установить именно `Homebrew.pkg` из официального release `Homebrew/brew`?» Дождись отдельного «да».

После установки выполни только те строки `Next steps`, которые напечатал официальный установщик. Перед каждой изменяющей shell-профиль строкой покажи её целиком и получи отдельное `да`. Не подставляй путь от другой архитектуры.

Повтори `verify.sh`.

## Шаг 3. Git

Если Git уже получил `PASS`, не устанавливай дубликат. Иначе используй Homebrew:

```bash
brew install git
```

**Approval-gate:** команда загрузит Git из Homebrew и изменит Homebrew prefix. Она не отправляет репозитории в сеть. Спроси: «Разрешаешь выполнить именно `brew install git`?» Дождись отдельного «да», затем повтори `verify.sh`.

Не записывай реальные `user.name` и `user.email` в state или документацию. Если проекту нужна Git identity, пользователь вводит её локально отдельным шагом.

## Шаг 4. GitHub CLI и вход

Если `gh` отсутствует:

```bash
brew install gh
```

**Approval-gate:** команда загрузит GitHub CLI из Homebrew и изменит Homebrew prefix. Спроси разрешение именно на эту команду, дождись «да» и повтори `verify.sh`.

Установка и вход — разные действия. Для входа покажи:

```bash
gh auth login --web --git-protocol https
```

**Approval-gate:** команда свяжется с GitHub, откроет browser/device flow и сохранит credential локально. Спроси разрешение именно на этот сетевой вход. Одноразовый код и данные аккаунта пользователь вводит только в официальном окне; в чат их не отправляет. После завершения повтори `verify.sh`, не публикуя сырой вывод `gh auth status`.

Затем отдельно покажи read-only команду:

```bash
gh auth status
```

Она может показать account identity. Получи отдельное согласие на сетевую проверку и попроси сообщить только `успех` или `ошибка`, без сырого вывода. Этот ручной результат не записывается в state.

## Шаг 5. Node.js

Если Node.js уже получил `PASS`, не переустанавливай его. Иначе:

```bash
brew install node
```

**Approval-gate:** команда загрузит текущий поддерживаемый Homebrew-пакет Node.js вместе с npm и изменит Homebrew prefix. Спроси разрешение именно на эту команду. После «да» выполни её и повтори `verify.sh`.

Не закрепляй номер версии в runbook. Перед новым проектом сверяй требования проекта и текущую LTS-линейку на официальной странице Node.js.

## Шаг 6. Python

`verify.sh` доказывает только наличие команды. Отдельно посмотри её источник:

```bash
command -v python3
```

Не удаляй и не заменяй Apple-controlled `/usr/bin/python3`: официальная документация Python предупреждает, что он принадлежит инструментам Apple. Если команда уже указывает на отдельную поддерживаемую project-установку, ничего не меняй. Если виден только Apple-controlled Python, установи отдельный Python для проектов:

```bash
brew install python
```

**Approval-gate:** команда загрузит Python из Homebrew и изменит Homebrew prefix. Спроси разрешение именно на эту команду, дождись «да», затем повтори `command -v python3` и `verify.sh` по одному.

Для будущих проектов создавай отдельный `venv`. Не запускай `sudo pip` и не ставь project dependencies глобально.

## Шаг 7. OpenAI Codex CLI

Используй только [официальную инструкцию OpenAI](https://learn.chatgpt.com/docs/codex/cli). В этом маршруте выбран прозрачный пакетный путь; не передавай сетевой ответ напрямую в shell.

Если `codex` отсутствует:

```bash
brew install --cask codex
```

**Approval-gate:** команда загрузит Codex CLI через Homebrew cask и добавит исполняемый файл в Homebrew prefix. Спроси разрешение именно на эту команду, дождись «да» и повтори `verify.sh`.

Установка не выполняет вход. Для первого входа покажи:

```bash
codex
```

**Approval-gate:** Codex установит сетевое соединение; пользователь вручную выбирает **Sign in with ChatGPT** и завершает официальный flow. Спроси отдельное разрешение на запуск. Пароль, device code, access token и API key не передаются в чат и не записываются в репозиторий. Успешное открытие интерактивной сессии подтверждается пользователем только как `успех`; затем он корректно выходит и повторяет `verify.sh`. Скрипт подтвердит команду, но не login.

## Шаг 8. Anthropic Claude Code

В этом маршруте используется опубликованный Anthropic Homebrew cask, а не download-and-execute pipeline.

Если `claude` отсутствует:

```bash
brew install --cask claude-code
```

**Approval-gate:** команда загрузит Claude Code через Homebrew и изменит Homebrew prefix. Спроси разрешение именно на эту команду, дождись «да» и повтори `verify.sh`.

Для первого входа покажи:

```bash
claude
```

**Approval-gate:** Claude Code свяжется с Anthropic и запустит официальный authentication flow. Спроси отдельное разрешение. Пользователь выбирает подходящий тип своего аккаунта локально и не отправляет пароль, код или токен в чат. Успешное открытие интерактивной сессии подтверждается только как `успех`; затем пользователь корректно закрывает её и повторяет `verify.sh`. Скрипт подтвердит команду, но не login.

## Чек-поинт

Когда итоговый запуск показывает все обязательные инструменты как `PASS`, а пользователь отдельно подтвердил успешный вход в `gh`, Codex и Claude без передачи account data, запиши:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh step 09-development:verified
```

**Checkpoint-gate:** команда добавит только allowlisted step-marker в локальный progress. Покажи её отдельно и дождись отдельного «да» именно на запись checkpoint.

Следующий шаг: `10-final-checkpoint/runbook.md`.
