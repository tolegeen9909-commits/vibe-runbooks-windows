# 07 · Контрольная блокировка, выход и перезагрузка

## Результат фазы

Мы отдельно проверим три сценария: заблокированный экран, выход из учётной записи и обычную перезагрузку. Первая перезагрузка выполняется только при физическом доступе к Mac mini.

Режимы оцениваются по-разному:

- в `secure` после перезагрузки разрешена локальная разблокировка FileVault и вход; приложения удалённого доступа после входа должны подняться сами;
- в `autonomous` после перезагрузки нельзя трогать Mac: automatic login и удалённые каналы должны восстановиться сами.

Успешный `secure`-тест не доказывает полностью автономный холодный старт.

Ручная процедура соответствует инструкции Apple [Shut down or restart your Mac](https://support.apple.com/guide/mac-help/mchlp2522/mac).

## Обязательная стоп-точка

До первого reboot пользователь должен лично подтвердить все три пункта:

1. Он находится рядом с Mac mini; подключены монитор, клавиатура и мышь.
2. **System Settings → General → Software Update** не показывает активную установку, подготовку или требование перезагрузки.
3. Все документы сохранены, приложения с несохранённой работой закрыты, длительные команды и копирование файлов остановлены.

Нужна точная фраза: «Физический доступ есть, обновление не идёт, несохранённой работы нет». Без неё не блокируй экран, не выходи из учётной записи и не перезагружай Mac.

## Шаг 1. Проверка блокировки

Сначала убедись, что SSH/Termius по Tailscale и AnyDesk работают с Windows-компьютера. Не копируй в чат IP, hostname, AnyDesk ID или полный вывод клиентов.

Покажи точное ручное действие: **Apple menu → Lock Screen**.

**Approval-gate:** экран Mac заблокируется; локальные приложения продолжат работать, но для возврата к рабочему столу понадобится пароль или разрешённая биометрия. Спроси: «Разрешаешь сейчас выбрать Apple menu → Lock Screen?» Дождись отдельного «да».

Пока экран заблокирован, с Windows выполни одно действие: открой новое подключение к сохранённому хосту в Termius. После успеха отдельно проверь управление через AnyDesk. Просмотр без управления не считается успехом.

Если оба канала работают, запиши только ручную проверку:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual lock-recovery
```

**Checkpoint-gate:** команда запишет только boolean-маркер успешного lock-теста. Покажи её отдельно и дождись отдельного «да».

Если канал не работает, разблокируй Mac локально, исправь только первый сбой по `TROUBLESHOOTING.md` и повтори этот шаг.

## Шаг 2. Проверка выхода из учётной записи

Выход может остановить пользовательские GUI-приложения. Он проверяет путь восстановления, но сам по себе не является обещанием круглосуточного доступа на экране входа.

Покажи точное ручное действие: **Apple menu → Log Out**.

**Approval-gate:** сеанс пользователя и его приложения закроются. Несохранённые данные можно потерять; после logout automatic login не выполняется автоматически. Спроси: «Разрешаешь сейчас выбрать Apple menu → Log Out?» Дождись отдельного «да».

После выхода попробуй с Windows открыть сохранённые SSH/Termius и AnyDesk-подключения. Зафиксируй только `работает` или `не работает`, без адресов и ID.

Затем войди локально в выбранную учётную запись. Не запускай Tailscale или AnyDesk вручную. Подожди, пока login items завершат запуск, и снова проверь оба удалённых канала с Windows.

Маркер означает, что поведение logout известно и удалённый доступ восстановился после обычного входа без ручного запуска приложений:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual logout-recovery
```

**Checkpoint-gate:** команда запишет только boolean-маркер проверенного logout recovery. Покажи её отдельно и дождись отдельного «да».

Если после входа доступ не вернулся, настрой автозапуск только проблемного приложения и повтори весь шаг logout.

## Шаг 3. Контрольная перезагрузка

Снова проверь обязательную стоп-точку в начале файла. Она нужна непосредственно перед reboot, даже если уже подтверждалась для logout.

Покажи точное ручное действие: **Apple menu → Restart… → снять “Reopen windows when logging back in” → Restart**.

**Approval-gate:** Mac немедленно завершит процессы и разорвёт удалённые сеансы. Ошибка настроек может оставить машину недоступной до локального вмешательства. Спроси: «Разрешаешь выполнить именно эту контрольную перезагрузку сейчас?» Дождись отдельного «да».

### Если выбран `secure`

1. Дождись экрана FileVault/login.
2. Разблокируй диск и войди локально.
3. Не запускай Tailscale и AnyDesk вручную.
4. С Windows проверь, что Mac снова online в Tailscale.
5. Открой новое подключение сохранённого хоста в Termius.
6. Отдельно открой AnyDesk и докажи управление, а не только картинку.

Это подтверждает восстановление **после локальной разблокировки**. До неё удалённый доступ не требуется и не должен называться автономным.

### Если выбран `autonomous`

После нажатия Restart не используй клавиатуру, мышь или монитор Mac. С Windows последовательно докажи:

1. Mac самостоятельно появился online в Tailscale.
2. Новое SSH/Termius-подключение по tailnet открылось.
3. AnyDesk подключился в режиме Unattended Access и позволяет управлять Mac.

Любое локальное действие до этих проверок отменяет autonomous-тест. Исправь одну причину и повтори полный reboot.

## Маркеры reboot

Записывай маркер только сразу после доказанного результата и по одному:

Каждая следующая команда — отдельное изменение локального `state/progress.json`. Перед каждой покажи точную команду, объясни название boolean-маркера и спроси: «Записать именно этот локальный checkpoint? Ответьте `да`». Одно согласие не разрешает следующую команду.

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual reboot-tailscale
```

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual reboot-ssh
```

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh manual reboot-anydesk
```

Когда все три результата подтверждены в соответствии с выбранным режимом:

```bash
./mac-mini-24x7/scripts/record-checkpoint.sh step 07-reboot-checkpoint:verified
```

Для step-marker также нужен новый **checkpoint-gate**: команда фиксирует только завершение фазы и не доказывает тесты сама.
