# Vibe Runbooks Windows

## Goal

Создать отдельный Windows-only репозиторий `vibe-runbooks-windows`, который проводит абсолютного новичка от чистой Windows 11 до настроенной среды вайбкодинга, первого Flutter-приложения на Android Emulator и/или первого опубликованного сайта на Netlify.

Комплект должен повторять учебную модель исходного `vibe-runbooks`: Codex читает `AGENTS.md`, ведёт человека по фазам, запускает по одному безопасному установочному действию, проверяет результат после каждой фазы и сохраняет точку продолжения.

## Users And Scenarios

### Основной пользователь

- взрослый новичок без опыта программирования и терминала;
- использует Windows 11 на обычном Intel/AMD-компьютере;
- умеет нажимать кнопки, копировать команду и отвечать гиду, но не обязан понимать Git, PowerShell, Flutter или деплой;
- общается с Codex по-русски на «ты».

### Основные сценарии

1. Пользователь устанавливает ChatGPT Desktop с режимом Codex и открывает локальную папку комплекта.
2. Codex автоматически читает `AGENTS.md`, выполняет предварительную проверку и ведёт пользователя по одной фазе за раз.
3. Базовый маршрут настраивает Windows, PowerShell, Git, GitHub CLI, Node.js, Claude Code и Codex CLI.
4. После базового маршрута пользователь выбирает мобильный трек, веб-трек, оба трека или осознанно пропускает дополнительный трек.
5. Мобильный трек устанавливает Flutter и Android Studio, создаёт Android Emulator, запускает первое Flutter-приложение и отправляет проект в приватный GitHub-репозиторий.
6. Веб-трек устанавливает Netlify CLI, создаёт первый статический сайт, отправляет его в приватный GitHub-репозиторий, сначала публикует preview и только после подтверждения — production URL.
7. После перерыва Codex читает сохранённый прогресс и продолжает с последнего завершённого шага.
8. При ошибке Codex сначала воспроизводит её, затем применяет одно исправление и повторяет ту же проверку.

## In Scope

### Платформа и оболочка

- Windows 11 x64 как основная и проверяемая платформа.
- Нативный агент Codex на Windows и PowerShell как основной shell.
- Совместимость установочных скриптов с Windows PowerShell 5.1 и PowerShell 7.
- `winget` как основной менеджер системных пакетов.
- Рабочий каталог по умолчанию `C:\Projects`.
- Инструкции по обновлению Windows, отображению расширений и скрытых файлов, проверке свободного места, виртуализации и шифрования устройства/BitLocker.

### Структура маршрута

- `00-preflight`: только чтение состояния компьютера, карта готовности и локальный маркер прогресса без изменения системных настроек.
- `01-windows-setup`: безопасные настройки Windows и ручные точки безопасности.
- `02-foundation`: Windows Terminal/PowerShell, `winget`, встроенный `tree` и базовые проверки.
- `03-git-github`: Git, GitHub CLI, Git identity, вход через браузер, глобальные исключения секретных файлов и Gitleaks pre-commit guard.
- `04-ai-helpers`: Node.js LTS, Claude Code, Codex CLI, вход через браузер и диагностика.
- `05-flutter`: Flutter SDK, Android Studio, Android SDK, лицензии и Android Emulator.
- `06-first-win`: первое Flutter-приложение, видимая правка, запуск, commit и push.
- `05w-netlify`: Netlify CLI и вход.
- `06w-first-site`: первый сайт, локальная проверка, commit, push, preview deploy и подтверждаемый production deploy.
- `07-checkpoint`: итоговая проверка по выбранным трекам и передача в LMS.
- `99-appendix-backend`: только справочная заготовка, не часть первого маршрута.

### Артефакты репозитория

- `AGENTS.md`, `FOR-CODEX.md`, `RITUALS.md`, `INDEX.md`, `README.md`, `TROUBLESHOOTING.md`.
- Русские `runbook.md` в каждой фазе.
- PowerShell-скрипты `*.ps1` для установок и проверок.
- Общая библиотека `scripts/lib.ps1` без скрытых внешних зависимостей.
- Идемпотентная запись прогресса в `state/progress.json` и `state/progress.log`.
- Шаблон проектного `AGENTS.md` и безопасный `.gitignore`.
- Windows-совместимый command guard для Claude Code, распознающий опасные Git-, PowerShell-, CMD- и download-and-execute-команды.
- Встроенные режимы разрешений Codex используются вместо попытки подключить Claude-хук к Codex.
- Автоматические тесты PowerShell-логики и маршрутизации в GitHub Actions на `windows-latest`.
- Проверки форматирования/анализа PowerShell, когда необходимые инструменты доступны в CI.

### Поведение гида

- Один шаг за раз, простые русские объяснения, понятный ожидаемый результат.
- Скрипт сам выполняет безопасные повторяемые действия и сообщает, что изменил.
- Явная остановка перед UAC/admin-действием, входом во внешний аккаунт, публикацией production, оплатой, удалением или другой труднообратимой операцией.
- Пароли, коды входа, recovery keys, API keys и токены никогда не запрашиваются в чате.
- Команды запускаются в видимом Windows Terminal/PowerShell пользователя, вход выполняется в системном браузере.
- Успех каждой фазы подтверждается отдельным `verify.ps1`.

## Out Of Scope

- Сборка, подпись и локальное тестирование iOS-приложений: Xcode и iOS Simulator требуют macOS.
- WSL/WSL2 в основном маршруте. Может быть добавлен позже отдельным необязательным приложением.
- Windows 10, Windows on ARM и корпоративно управляемые машины как гарантированно поддерживаемые платформы.
- Автоматическое изменение BIOS/UEFI, автоматическое включение BitLocker или сохранение recovery key.
- Автоматический ввод паролей, кодов 2FA, токенов либо обход политик организации.
- Публикация мобильного приложения в Google Play.
- Docker, базы данных, Railway и полноценный backend в MVP.
- Графический установщик `.exe`/`.msi`; MVP представляет собой управляемый Codex маршрут с PowerShell-скриптами.
- Полная визуальная идентичность macOS-инструкции; сохраняются маршрут и педагогика, а системные действия заменяются корректными Windows-аналогами.

## Constraints

- Проект должен оставаться понятным новичку и не требовать предварительного знания PowerShell.
- Каждый скрипт должен быть идемпотентным либо явно останавливаться до повторно небезопасного действия.
- По умолчанию скрипты запускаются без прав администратора. Повышение прав допускается только в конкретном, объяснённом шаге.
- Нельзя отключать Windows Defender, Firewall, UAC или системную защиту ради успешной установки.
- Нельзя использовать непроверенные зеркала, случайные download-сайты и захардкоженные версии, которые быстро устареют.
- Перед установкой пакет проверяется через `winget`; скрипт должен корректно распознавать уже установленный пакет.
- Для официальных инструментов используются официальные package IDs или официальные страницы загрузки.
- Все новые проекты включают `.env*` в `.gitignore`, сохраняя безопасные `.env.example`, `.env.sample` и `.env.template`.
- GitHub-репозитории для учебных проектов создаются приватными по умолчанию.
- Production deploy требует явного подтверждения пользователя; preview deploy может быть подготовлен раньше.
- Кодировка файлов — UTF-8; пути и команды должны корректно работать при русском имени пользователя Windows, но SDK и проекты по умолчанию размещаются в коротких ASCII-путях.
- Репозиторий использует Git, отдельную feature-ветку, сфокусированные коммиты и pull request; прямой push в `main` не используется.
- Репозиторий первоначально публикуется на GitHub как private под именем `vibe-runbooks-windows`; после приёмки владелец явно изменил его видимость на public для свободного клонирования.
- В `AGENTS.md` проекта присутствует обязательный раздел `Open Design MCP For Design Work`, хотя UI-дизайн не входит в MVP.

## Acceptance Criteria

1. На чистой поддерживаемой Windows 11 x64 пользователь может открыть репозиторий в Codex и получить первый конкретный шаг без чтения внутренних файлов вручную.
2. `00-preflight` выводит версию/архитектуру Windows, память, свободное место, состояние `winget`, виртуализации и уже установленных инструментов, не меняет системные настройки и записывает только локальный маркер прогресса.
3. Для каждой основной фазы существует понятный `runbook.md`, хотя бы один исполняемый или явно ручной шаг и `verify.ps1` с корректным exit code.
4. Повторный запуск завершённых установочных скриптов не создаёт дублей и не ломает конфигурацию.
5. Базовый маршрут устанавливает и проверяет Git, `gh`, Node/npm, Claude Code и Codex CLI; браузерные входы остаются за пользователем.
6. `gh auth status` и Git identity проверяются до создания учебных репозиториев.
7. Gitleaks guard блокирует тестовый staged secret и пропускает обычный коммит; безопасные env-шаблоны не игнорируются.
8. Command guard проходит автоматические тесты и блокирует как минимум force-push в `main`, `git reset --hard`, `git clean -f`, опасный `Remove-Item`/`rd`, удаление `.env`, форматирование диска и `irm`/`iwr` с немедленным `iex`.
9. Мобильный трек доводит пользователя до работающего Flutter-приложения на Android Emulator либо выдаёт точную диагностическую карту и один следующий шаг.
10. Веб-трек доводит пользователя до локально проверенного сайта, приватного GitHub-репозитория, preview URL и — после явного подтверждения — production URL Netlify.
11. `07-checkpoint/self-check.ps1` формирует итог по реально выбранным трекам, не требует Xcode/CocoaPods и сохраняет результат в state.
12. GitHub Actions запускает тесты на Windows и завершается успешно.
13. README содержит отдельный «чистый Windows → Codex → открыть папку → одно стартовое сообщение» маршрут.
14. `TROUBLESHOOTING.md` покрывает отсутствующий `winget`, PowerShell execution policy, PATH после установки, Git Bash, GitHub/Claude/Codex/Netlify login, Android licenses, выключенную виртуализацию, Android Emulator, длинные пути, Defender quarantine и повторный запуск после ошибки.
15. Репозиторий создан на GitHub как private, `origin` настроен, feature-ветка отправлена и pull request открыт после успешной проверки.
